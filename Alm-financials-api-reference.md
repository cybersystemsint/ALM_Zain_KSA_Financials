# ALM Financials — Frontend API Reference

**Base URL:** `http://194.164.17.17:8080/alm_ksa_financials`
**Date:** March 2026

---

> **Architecture — Pre-Warm Export Pattern**
>
> Large unfiltered exports are pre-generated in the background by schedulers:
>
> - **Unfiltered export** (no body / empty `filterBy`) → trigger response returns `status: COMPLETED` immediately. Skip polling. Download at once.
> - **Filtered export** (any `filterBy` / `dateFrom` / `dateTo`) → runs on-demand. Response returns `status: RUNNING`. Use the poll + download flow.
> - **Auto-refresh triggers:**
>   - **Depreciation scheduler** → refreshes both `depreciation` and `far_report` exports (depreciation mutates FAR records)
>   - **Unmapped reconciliation scheduler** → refreshes each unmapped export after its own run
>   - **FAR upload** → refreshes the `far_report` export after every bulk upload completes
> - **Excel sheet splitting** — exports with >1,000,000 rows automatically split into Sheet1, Sheet2, … (1M rows each). Single `.xlsx` download.

### 1.3 Export (Async)

> **Pre-warm behaviour (no body / empty filterBy):**
> File is pre-generated by the scheduler. Trigger response returns `status: COMPLETED` immediately with a `downloadUrl`. **Skip polling — download at once.**
>
> **On-demand behaviour (with filterBy / dateFrom / dateTo):**
> Runs a fresh export. Response returns `status: RUNNING`. Use the poll + download flow below.

#### Step 1 — Trigger

```
POST /depreciation-history/export?format=CSV
POST /depreciation-history/export?format=EXCEL
```

Optional request body — omit entirely for unfiltered (pre-warmed) export:

```json
{
  "columnName": "category",
  "searchQuery": "TOWER",
  "filterBy": { "statusFlag": "ACTIVE" },
  "dateFrom": "2024-01-01T00:00:00",
  "dateTo": "2024-12-31T23:59:59"
}
```

**Response — pre-warmed (no polling needed):**
```json
{
  "success": true,
  "data": {
    "jobId":       "prewarm-depreciation-EXCEL",
    "status":      "COMPLETED",
    "pollUrl":     "/exports/status/prewarm-depreciation-EXCEL",
    "downloadUrl": "/exports/download/prewarm-depreciation-EXCEL"
  }
}
```

**Response — on-demand filtered (poll until COMPLETED):**
```json
{
  "success": true,
  "data": {
    "jobId":       "a1b2c3d4",
    "status":      "RUNNING",
    "pollUrl":     "/exports/status/a1b2c3d4",
    "downloadUrl": "/exports/download/a1b2c3d4"
  }
}
```

#### Step 2 — Poll Status (on-demand only)

```
GET /exports/status/{jobId}
```

Poll every 3 seconds until `status` is `COMPLETED` or `FAILED`.

**RUNNING:**
```json
{
  "success": true,
  "data": {
    "jobId": "a1b2c3d4",
    "exportType": "depreciation",
    "status": "RUNNING",
    "preWarmed": false,
    "startedAt": "2026-03-01T22:00:00",
    "completedAt": null,
    "totalRows": 3000000,
    "processedRows": 1860000,
    "progressPercent": 62
  }
}
```

| Field | Use |
|-------|-----|
| `progressPercent` | Progress bar width (0–100) |
| `processedRows` | Display: "1,860,000 rows exported..." |
| `totalRows` | Display: "... of 3,000,000" |

**COMPLETED — on-demand (has `expiresAt`):**
```json
{
  "success": true,
  "data": {
    "status": "COMPLETED",
    "preWarmed": false,
    "progressPercent": 100,
    "downloadUrl": "/exports/download/a1b2c3d4",
    "expiresAt": "2026-03-02T00:00:00"
  }
}
```

**COMPLETED — pre-warmed (no `expiresAt`, file persists until scheduler replaces it):**
```json
{
  "success": true,
  "data": {
    "status": "COMPLETED",
    "preWarmed": true,
    "progressPercent": 100,
    "downloadUrl": "/exports/download/prewarm-depreciation-EXCEL"
  }
}
```

**FAILED:**
```json
{
  "success": true,
  "data": {
    "status": "FAILED",
    "progressPercent": 18,
    "error": "Database connection timeout"
  }
}
```

#### Step 3 — Download

```
GET /exports/download/{jobId}
```

> **Auto-download:** when `status === "COMPLETED"`, immediately call `window.open(BASE_URL + downloadUrl)`. No manual click required.
>
> - **On-demand files** — show `expiresAt` countdown and a re-download button (default retention: 2 hours).
> - **Pre-warmed files** (`preWarmed: true`) — no `expiresAt`. File persists until the scheduler replaces it. Do not show an expiry timer.
> - Always show a **[Re-download]** button as fallback in case the browser blocks the popup.

### 1.4 Run Depreciation Scheduler (Manual Trigger)

> After `processDepreciation()` completes — whether triggered by cron or manually — both the depreciation **and** FAR report pre-warmed exports are automatically refreshed inside the scheduler's `finally` block. The next unfiltered export request for either dataset will return `COMPLETED` instantly with fresh data.

```
POST /depreciation-history/run-depreciation
GET  /depreciation-history/run-depreciation/status
```

```json
// 200 — triggered
{ "success": true, "data": "Depreciation scheduler triggered successfully" }

// 409 — already running
{ "success": false, "message": "Depreciation scheduler is already running" }

// Status
{ "success": true, "data": "RUNNING" }
{ "success": true, "data": "IDLE" }
```

> **Pre-warm refresh triggers:**

## 4. Export Status — Full Field Reference

Returned by `GET /exports/status/{jobId}` (shared endpoint) and `GET /api/far/export/{jobId}/status` (FAR-specific). All export types share this structure.

| Field | Type | When Present | Description |
|-------|------|--------------|-------------|
| `jobId` | string | Always | The export job identifier |
| `exportType` | string | Always | `depreciation`, `unmapped_active`, `unmapped_passive`, `unmapped_it`, `far_report` |
| `status` | string | Always | `RUNNING`, `COMPLETED`, or `FAILED` |
| `preWarmed` | boolean | Always | `true` when served from background pre-warm cache; `false` for on-demand |
| `startedAt` | string | Always | ISO datetime when export started |
| `completedAt` | string | When done | ISO datetime when export finished |
| `totalRows` | long | Always | Total rows in the export |
| `processedRows` | long | Always | Rows written so far |
| `progressPercent` | int | Always | 0–100, use for progress bar width |
| `downloadUrl` | string | COMPLETED only | Path to download the file |
| `expiresAt` | string | COMPLETED + on-demand only | ISO datetime when file is auto-deleted. Absent for pre-warmed exports — they persist until the scheduler replaces them |
| `error` | string | FAILED only | Human-readable error message |

## 5. Frontend Implementation Guide

### 5.1 Export Flow

> **Critical:** check `status` in the **initial trigger response**.
> If `status === "COMPLETED"` → pre-warmed, skip polling, download immediately.
> Only start the polling loop when `status === "RUNNING"` or `status === "ACCEPTED"`.

#### UX — Global Export Toast

Place one global toast component in your root layout. It persists across page navigation and handles all export jobs.

```
RUNNING (on-demand):
┌──────────────────────────────────────────────────┐
│  📦 Exporting FAR Report (EXCEL)                 │
│  ████████████░░░░░░░░  62%  (53,000 / 85,000)   │
│                                          [Cancel]│
└──────────────────────────────────────────────────┘

RUNNING (pre-warm loading at startup):
┌──────────────────────────────────────────────────┐
│  📦 Loading cached export... (Unmapped Active)   │
│  ████████████████████  85%  (1,130,000 / 1.3M)  │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│  ✅ Export ready — downloading...                 │
```

#### Step-by-Step Code Flow

```
1. User clicks 'Export' button
   ↓
2. POST to the appropriate export endpoint:
     /depreciation-history/export?format=EXCEL
     /unmapped-inventory/active/export?format=EXCEL
     /api/far/export?format=EXCEL
   ↓
3. Read trigger response: { jobId, status, downloadUrl }
   ↓
4a. status === 'COMPLETED'  →  PRE-WARMED PATH            ← CHECK THIS FIRST
    → window.open(BASE_URL + downloadUrl)
    → Show 'Export ready — downloading...' toast
    → preWarmed === true: no expiresAt, don't show expiry timer
    → Show [Re-download] button as fallback
    → DONE — no polling needed
   ↓
4b. status === 'RUNNING' or 'ACCEPTED'  →  ON-DEMAND PATH
    → Store jobId in GLOBAL state (Redux / Vuex / Context / Signal)
      NOT component state — survives page navigation
    → Show progress toast
    → Start polling the appropriate status endpoint every 3 seconds:
        /exports/status/{jobId}            (depreciation, unmapped)
        /api/far/export/{jobId}/status     (FAR)
   ↓
5. Each poll tick:
    → progressPercent      → progress bar width
    → processedRows / totalRows  → '53,000 / 85,000 rows'
    → preWarmed === true   → show 'Loading cached export...' label
   ↓
6. status === 'COMPLETED':
    → clearInterval
    → window.open(BASE_URL + downloadUrl)
       For FAR: window.open(BASE_URL + '/api/far/export/' + jobId + '/download')
    → preWarmed === false: show expiresAt countdown
    → Show [Re-download] button
   ↓
7. status === 'FAILED':
    → clearInterval
    → Show error toast with data.error message + [Retry] button
```

#### JavaScript Implementation

```javascript
const BASE_URL = 'http://194.164.17.17:8080/alm_ksa_financials';

// Endpoint mapping for poll and download
const EXPORT_CONFIG = {
  depreciation:     { poll: (id) => `/exports/status/${id}`,              download: (id) => `/exports/download/${id}` },
  unmapped_active:  { poll: (id) => `/exports/status/${id}`,              download: (id) => `/exports/download/${id}` },
  unmapped_passive: { poll: (id) => `/exports/status/${id}`,              download: (id) => `/exports/download/${id}` },
  unmapped_it:      { poll: (id) => `/exports/status/${id}`,              download: (id) => `/exports/download/${id}` },
  far_report:       { poll: (id) => `/api/far/export/${id}/status`,       download: (id) => `/api/far/export/${id}/download` },
};

async function triggerExport(endpoint, format, exportType, filterBody = null) {
  const res = await fetch(`${BASE_URL}${endpoint}?format=${format}`, {
    method: 'POST',
    headers: filterBody ? { 'Content-Type': 'application/json' } : {},
    body: filterBody ? JSON.stringify(filterBody) : null,
  });
  const json = await res.json();
  const data = json.data || json; // FAR controller returns flat, others wrap in data

  showExportToast({ type: exportType, format });

  // Pre-warmed: already done, skip polling
  if (data.status === 'COMPLETED') {
    const downloadPath = data.downloadUrl || EXPORT_CONFIG[exportType].download(data.jobId);
    window.open(BASE_URL + downloadPath);
    updateToastCompleted({ ...data, isPreWarmed: true });
    return;
  }

  // On-demand or pre-warm still loading at startup
  const config = EXPORT_CONFIG[exportType];
  return pollExportStatus(data.jobId, config.poll(data.jobId), config.download(data.jobId));
}

function pollExportStatus(jobId, pollPath, downloadPath) {
  const interval = setInterval(async () => {
    try {
      const res = await fetch(BASE_URL + pollPath);
      const json = await res.json();
      const data = json.data || json;

      updateProgressBar(data.progressPercent);
      updateRowCount(data.processedRows, data.totalRows);
      if (data.preWarmed) updateToastLabel('Loading cached export...');

      if (data.status === 'COMPLETED') {
        clearInterval(interval);
        const dlPath = data.downloadUrl || downloadPath;
        window.open(BASE_URL + dlPath);
        updateToastCompleted(data);
        if (!data.preWarmed && data.expiresAt) showExpiry(data.expiresAt);

      } else if (data.status === 'FAILED') {
        clearInterval(interval);
        showErrorToast(data.error, () => { /* retry logic */ });
      }
    } catch (e) {
      console.error('Poll error', e);
    }
  }, 3000);

  return interval;
}

// ── Usage examples ──────────────────────────────────────────────────────────

// Unfiltered depreciation export (pre-warmed — instant)
triggerExport('/depreciation-history/export', 'EXCEL', 'depreciation');

// Filtered depreciation export (on-demand — poll)
triggerExport('/depreciation-history/export', 'EXCEL', 'depreciation', {
  filterBy: { statusFlag: 'ACTIVE' },
  dateFrom: '2024-01-01T00:00:00',
});

// Unfiltered FAR export (pre-warmed — instant)
triggerExport('/api/far/export', 'EXCEL', 'far_report');

// Filtered FAR export (on-demand — poll)
triggerExport('/api/far/export', 'EXCEL', 'far_report', {
  filterBy: { category: 'IT Equipment' },
});

// Unmapped active export
triggerExport('/unmapped-inventory/active/export', 'EXCEL', 'unmapped_active');

// FAR upload
async function uploadFar(rows, source = 'Excel') {
  const res = await fetch(`${BASE_URL}/api/far/upload?source=${source}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(rows),
  });
  const result = await res.json();
  // result: { status, inserted, updated, failed, total, elapsedMs }
  return result;
}
```

#### Important Notes

- **Check `status` in initial trigger response** — if `COMPLETED`, skip polling entirely
- **Store `jobId` in global state** — component state is lost on navigation
- **Multiple exports can run simultaneously** — store as an array of active jobs
- **Poll every 3 seconds** — balances responsiveness vs server load
- **Always `clearInterval`** when status reaches `COMPLETED` or `FAILED`
- **Auto-download via `window.open(downloadUrl)`** on `COMPLETED` — don't wait for user click
- **Always show `[Re-download]`** in case browser blocks the auto-download popup
- **`preWarmed: true`** → no `expiresAt`, don't show expiry countdown
- **`preWarmed: false`** → show `expiresAt` countdown (default retention: 2 hours)
- **FAR uses its own endpoint paths** (`/api/far/export/{id}/status` and `/api/far/export/{id}/download`) while depreciation and unmapped use the shared `/exports/` endpoints

### 5.2 FAR Upload Flow

```
User selects file (Excel or CSV)
  ↓
Frontend parses file into JSON array of row objects
  ↓
POST /api/far/upload?source=Excel
  Content-Type: application/json
  Body: [ { "assetId": "...", "cost": 250000, ... }, ... ]
  ↓
Response: { status: "SUCCESS", inserted: 142, updated: 58, failed: 0 }
  ↓
Show summary toast:
  ✅ Upload complete: 142 inserted, 58 updated, 0 failed (3.4s)
  ↓
Note: FAR pre-warmed export is automatically refreshed in background.
      The next unfiltered FAR export will return COMPLETED instantly.
```

**Error handling:**

| `status` | Meaning | UI Action |
|----------|---------|-----------|
| `"SUCCESS"` | All rows processed | Green success toast |
| `"PARTIAL"` | Some rows failed | Yellow warning toast, show `failed` count |
| `"ERROR"` | Entire upload rejected (e.g. empty payload) | Red error toast |

### 5.3 Scheduler Trigger Flow

```
User clicks 'Run Depreciation'
  ↓
POST /depreciation-history/run-depreciation
  ↓
409 → show 'Already running'
200 → show 'Triggered' toast
  ↓
Optionally poll: GET /depreciation-history/run-depreciation/status
  ↓
When scheduler completes (IDLE):
  → Depreciation pre-warmed export refreshed automatically
  → FAR report pre-warmed export refreshed automatically
    (because depreciation modifies FAR records)
  → Next unfiltered export for either dataset returns COMPLETED instantly
```

### 5.4 Reconciliation Trigger Flow

```
POST /unmapped-inventory/reconcile/active  (or passive / it / all)
  ↓
409 → show 'Already running'
200 → show 'Triggered' toast
  ↓
Poll: GET /unmapped-inventory/reconcile/status
  ↓
When reconciliation completes:
  reconcile/active  → prewarm-unmapped_active-EXCEL refreshed
  reconcile/passive → prewarm-unmapped_passive-EXCEL refreshed
  reconcile/it      → prewarm-unmapped_it-EXCEL refreshed
  reconcile/all     → all three refreshed
```

### Pre-Warmed Job IDs

These IDs are deterministic and returned automatically in the trigger response. Read `jobId` from the trigger response — you do not need to hardcode these.

| Job ID | Dataset | Refreshed after |
|--------|---------|-----------------|
| `prewarm-depreciation-EXCEL` | Depreciation History | Every depreciation run (scheduled + manual) |
| `prewarm-far_report-EXCEL` | FAR Report | Every FAR upload + every depreciation run |
| `prewarm-unmapped_active-EXCEL` | Unmapped Active | Active or full reconciliation |
| `prewarm-unmapped_passive-EXCEL` | Unmapped Passive | Passive or full reconciliation |
| `prewarm-unmapped_it-EXCEL` | Unmapped IT | IT or full reconciliation |

> **Startup warm-up:** when the application starts, all five pre-warmed exports are generated automatically in the background via `@EventListener(ApplicationReadyEvent.class)`. If a user requests an unfiltered export during this window, they will receive `status: RUNNING` and poll as normal — the file will be ready within a few minutes.
